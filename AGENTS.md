# AGENTS.md

## Проект
Этот репозиторий содержит сайт компании TechSupport.

Ключевое позиционирование:
**TechSupport — внешний IT-отдел для бизнеса.**

Главная бизнес-цель сайта:
получать заявки на **абонентское IT-обслуживание**.

Вторичная цель:
продавать входные услуги, которые затем переводят клиента на регулярное сопровождение.

Основные входные услуги:
- настройка Wi-Fi и сети
- видеонаблюдение
- инфраструктура для 1С
- VPN между офисами и удалёнными сотрудниками

Регион:
- Казань, Татарстан
- текущий фокус — локальный рынок
- в перспективе возможен выход в другие регионы России

Формат работы:
- смешанный
- удалённая поддержка + выезды на объекты

Факты о компании:
- на рынке с 2014 года
- в команде 5 человек
- основной коммерческий фокус — абонентское IT-обслуживание

## Целевая аудитория
Сайт рассчитан на бизнес, у которого уже есть IT-инфраструктура.

Типовые сегменты:
- офисы
- склады
- магазины
- клиники
- HoReCa
- логистика
- стройка
- производство
- филиальные компании
- малый и средний бизнес

Должность ЛПР не является главным критерием.

Для нас важнее:
- нормальная коммуникация
- возможность согласовывать работы
- возможность принимать или влиять на решение о сотрудничестве

## Что важно для клиентов
На сайте нужно говорить не с позиции технологий, а с позиции проблем бизнеса.

Типовые боли клиентов:
- нестабильный интернет и Wi-Fi
- проблемы с 1С
- сбои принтеров и рабочих мест
- проблемы с офисными программами
- слабая локальная сеть
- VPN между офисами и сотрудниками
- хранение данных и резервное копирование
- видеонаблюдение
- нестабильная работа компьютеров
- отсутствие системной IT-поддержки

---

## Стратегия сайта
Это не просто каталог IT-услуг.

Сайт должен продавать идею того, что TechSupport — это внешний IT-отдел для бизнеса.

Основная логика конверсии:
1. Показать боли и задачи бизнеса
2. Показать, что TechSupport берёт IT-инфраструктуру на себя
3. Показать, как работает регулярное сопровождение
4. Усилить доверие
5. Подвести к заявке, консультации или аудиту

Главную страницу нельзя перегружать всем списком технических услуг.

Главную страницу нужно оптимизировать под:
- понятность
- доверие
- заявки
- перевод клиента на абонентское обслуживание

## Правила текста
Писать на русском языке.

Стиль:
- деловой
- сжатый
- конкретный
- понятный
- без воды
- профессиональный

Нужно:
- объяснять технические вещи простым языком для бизнеса
- показывать, какую проблему клиента решает каждая услуга
- делать акцент на результате для компании
- писать ясно и без перегруза

Не использовать:
- «под ключ»
- «мы не просто чиним компьютеры»
- «индивидуальный подход»
- «команда профессионалов»
- «динамично развивающаяся компания»
- пустые рекламные обещания
- агрессивные маркетинговые клише
- слишком технический язык на главной странице

Предпочтительные формулировки:
- «внешний IT-отдел»
- «обслуживание, поддержка и развитие IT-инфраструктуры»
- «абонентское IT-обслуживание»
- «поддержка пользователей, сети, 1С, VPN, серверов и резервного копирования»
- «удалённо и с выездом»

## Приоритеты коммуникации
Главное сообщение сайта:
**TechSupport — внешний IT-отдел для бизнеса.**

Дополнительное сообщение:
мы берём на себя обслуживание, поддержку и развитие IT-инфраструктуры компании.

Бизнес-результаты, на которые нужно делать акцент:
- меньше сбоев и простоев
- предсказуемая поддержка
- один подрядчик по ключевым IT-вопросам
- стабильная работа сотрудников и инфраструктуры
- понятная зона ответственности
- регулярное сопровождение вместо хаотичных разовых ремонтов

Не выводить на первый план:
- виртуализацию
- Docker
- Prometheus
- Linux-администрирование
- другие глубокие технические темы

Эти темы можно раскрывать на внутренних страницах, но не в главном сообщении сайта.

## Приоритеты структуры главной страницы
Предпочтительный порядок секций:

1. Первый экран
2. Боли и типовые задачи клиентов
3. Что входит во внешний IT-отдел
4. Как работает TechSupport
5. Кейсы / примеры / доверие
6. Тарифы или модель сотрудничества
7. Финальный CTA / контакты

Первый экран должен:
- чётко доносить позиционирование
- содержать 1 основную кнопку
- содержать 1 вторичную кнопку
- избегать слабых и шаблонных формулировок
- не использовать спорные промо-обещания без подтверждения

## Принципы дизайна и UX
Направление дизайна:
- современный
- спокойный
- уверенный
- деловой
- тёмная тема допустима

Предпочтительно:
- хорошая читаемость
- сильная визуальная иерархия
- нормальные отступы
- аккуратное использование градиентов и свечения
- кнопки с понятными действиями
- карточки с ясной структурой
- ощущение надёжности, а не “кричащего” лендинга

Избегать:
- слишком активного фона, который мешает читать
- декоративных эффектов, которые сильнее смысла
- слишком большого количества акцентов на одном экране
- перегруженных карточек тарифов
- проблем с мобильной навигацией
- хаотичной структуры секций

## Правила разработки
Не переписывать проект с нуля без явной необходимости.

Базовый подход:
- сохранять рабочую основу
- делать рефакторинг поэтапно
- улучшать структуру, тексты, UX и поддержку кода постепенно

Перед крупными изменениями:
- изучить текущее состояние
- описать план
- только потом вносить изменения

При изменении кода:
- держать diff чистым
- не переписывать без необходимости
- сохранять рабочие assets, если нет причины их менять
- предпочитать понятную и переиспользуемую структуру, а не одноразовые хаки

Если assets находятся в беспорядке:
- сначала предложить план очистки
- потом безопасно переименовывать и переносить
- перед удалением проверять ссылки в HTML/CSS/JS

## Рабочий процесс
Для нетривиальных задач:
1. провести аудит текущего состояния
2. выявить проблемы
3. предложить план
4. реализовать согласованный этап
5. кратко зафиксировать, что изменено

При работе с текстами:
- всегда сверять их с текущим позиционированием
- переводить технические услуги на язык бизнеса
- держать в центре абонентское обслуживание

При работе с секциями:
- сначала улучшать понятность
- затем конверсию
- затем визуальную полировку
